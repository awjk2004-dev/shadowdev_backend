تقرير إصلاح اتصال قاعدة البيانات
=================================

التاريخ: 2026-10-15
المشروع: ShadowDev Backend

1. المشكلة الأصلية
-------------------
أظهر endpoint الخاص بفحص الصحة:

  "api": "healthy"
  "database": "error: (pymysql.err.OperationalError) (1045, ...
  "Access denied for user 'shadowdev_user'@'localhost' (using password: YES)"

كان تطبيق FastAPI يعمل ويستجيب، لكن MySQL رفض مصادقة المستخدم. يعرض
المسار /health حالة API وحالة قاعدة البيانات كلًّا على حدة، لذلك كانت
حالة API سليمة بينما اتصال قاعدة البيانات فاشلًا.

2. الفحوصات التي أُجريت
-----------------------
- إعداد الاتصال في ملف .env كان يستخدم المضيف localhost والمنفذ 3306،
  والمستخدم shadowdev_user، وقاعدة البيانات shadowdev.
- كلمة المرور في .env كانت موجودة وليست القيمة التوضيحية الموجودة في
  .env.example. لم تُعرض كلمة المرور أو تُكتب في هذا التقرير.
- تأكدنا أن إعدادات التطبيق الفعلية تطابق القيم الموجودة في .env، وأن
  متغير DB_PASSWORD في بيئة التشغيل لا يستبدل قيمة الملف بقيمة مختلفة.
- نجح الدخول الإداري إلى MySQL بعد تشغيل الأمر من Bash وإدخال كلمة مرور
  sudo في الطرفية. إصدار MySQL الظاهر كان 8.0.46.
- أظهر فحص MySQL أن الحساب shadowdev_user@localhost وقاعدة البيانات
  shadowdev موجودان.

3. الإصلاح المنفّذ
------------------
- عُيّنت كلمة مرور حساب MySQL shadowdev_user@localhost لتطابق قيمة
  DB_PASSWORD الموجودة في .env.
- مُنح الحساب صلاحية الوصول إلى قاعدة البيانات shadowdev باستخدام:

  GRANT ALL PRIVILEGES ON shadowdev.* TO 'shadowdev_user'@'localhost';

- لم تُغيّر قيمة كلمة المرور في هذا التقرير، ولم تُضمّن أي كلمة مرور.

4. التحقق بعد الإصلاح
---------------------
- اتصال التطبيق بقاعدة البيانات باستخدام إعداداته الحالية نجح.
- نُفّذ الاستعلام SELECT 1 وأعاد القيمة 1.
- شُغّل خادم التطوير بالأمر:

  venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

- أعاد endpoint /health النتيجة:

  {"api":"healthy","database":"connected"}

النتيجة: مشكلة مصادقة MySQL حُلّت، واتصال قاعدة البيانات سليم وفق آخر
اختبار أُجري.

5. ملاحظة منفصلة عن Zsh
-----------------------
ظهر التحذير:

  zsh: corrupt history file /home/ahmed/.zsh_history

هذا التحذير متعلق بملف سجل أوامر Zsh، وليس بخدمة MySQL أو اتصال التطبيق.
استخدام Bash سمح بتنفيذ أوامر MySQL الإدارية. لم يُصلح ملف سجل Zsh ضمن
هذا العمل، لأن ذلك منفصل عن مشكلة قاعدة البيانات.

6. ملفات المشروع
----------------
لم تُعدّل ملفات التطبيق أو إعداداته أثناء إصلاح اتصال قاعدة البيانات.
هذا التقرير هو الملف الجديد الوحيد الناتج عن الطلب.
